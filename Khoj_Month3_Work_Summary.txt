4. IMPLEMENTATION & TECHNICAL DETAILS (MONTH 3)
================================================================================
- Payment Architecture:
  1. Order Creation Endpoint: POST /v1/payments/create-order validates bookingId and amount, generating a unique orderId and returning Razorpay checkout configuration.
  2. Signature Verification & Receipt Endpoint: POST /v1/payments/verify captures razorpayPaymentId, marks booking as paid, and issues a verified digital QR ticket payload.

- Chat Engine Architecture:
  1. Slide-out ChatDrawer component mounted on MyBookings cards allowing instant communication between client and assigned provider.
  2. GET /v1/chat/:bookingId retrieves message history; POST /v1/chat/send appends new messages with timestamps and triggers provider auto-confirmation.

- Admin Dashboard Architecture:
  1. Overview metrics calculating platform revenue, verified merchants, and system readiness.
  2. Action queue allowing Super Admin to review pending merchant listings and update verification flags dynamically.

5. TECHNICAL CHALLENGES FACED & SOLUTIONS APPLIED
================================================================================

[CHALLENGE 1] Handling Payment Gateway Order Verification & State Sync
- Solution Applied: Engineered a 2-stage verification flow (Order Initialization -> Signature Verification) with fallback in-memory payment ledger ensuring instant status updates and QR receipt issuance even during cloud network latency.

[CHALLENGE 2] Managing Direct Messaging State Across Components
- Solution Applied: Encapsulated chat state in a reusable slide-out ChatDrawer component with RESTful persistence endpoints (/v1/chat/:bookingId) and optimistic UI updates for zero chat lag.

[CHALLENGE 3] Enforcing Super Admin Security Boundaries
- Solution Applied: Protected /khoj-services/admin route via PrivateRoutes middleware checking authentication tokens and adding role tags (Merchant vs Customer vs Administrator) in the global user context.
